# Roadmap Board — 기획안 (v0.9 / 시안 공유용)

작성: 2026-09-23 · 상태: **시안(Prototype) 검토 요청** · 산출물: `index.html` 단일 파일 시안 + 본 문서

## 1. 배경과 목적

Project Machina의 1차년도 실행계획은 현재 PPT 도형으로 관리되고 있다. 도형 기반 관리는 다음 문제를 갖는다.

| 문제 | 영향 |
|---|---|
| 일정이 시간축에 정렬되지 않음 | "10월 말에 무엇이 동시에 몰려 있는가"를 읽을 수 없음 |
| 변경 시 도형을 다시 그려야 함 | 주간 단위 갱신이 사실상 중단됨 |
| 선후행 관계가 화살표 그림으로만 존재 | 선행 일정이 밀렸을 때 영향 범위를 추적할 수 없음 |
| 상태(진행/지연/보류) 표기 체계 없음 | 회의 때마다 구두로 확인 |

**목적**: 구글 캘린더 주간 화면의 인지 모델(세로 = 시간축, 세로 실선 = 구획, 가로 = 병렬 트랙)을 그대로 차용해, 과제 트랙별 일정을 **시간축 위에 정렬된 상태로 편집·공유**한다.

**비목적 (Out of Scope)**: 공수/원가 관리, 리소스 배정, WBS 번호 체계, 결재 워크플로. 이 도구는 *보고·합의용 시각화 보드*이며 PMS를 대체하지 않는다.

## 3. 정보 구조 (데이터 모델)

단일 JSON 문서. 현재 시안은 `localStorage` 1개 키(`dr-roadmap-v2`)에 통째로 저장한다.

```jsonc
{
  "meta": { "start": "2026-09-21", "end": "2027-04-04" },
  "tracks": [
    { "id": "t0", "lab": "요구사항 4", "name": "통합 모니터링 시스템" }
  ],
  "items": [
    {
      "id": "e10",
      "t":  "t0",            // 트랙 id (FK)
      "sp": 1,               // 트랙 병합 폭 (1 = 단일 트랙, 2 = 2개 트랙에 걸침)
      "s":  "2026-10-01",    // 시작 (inclusive)
      "e":  "2026-10-31",    // 종료 (inclusive, 마일스톤은 s와 동일)
      "ti": "1년차 과제 제출용 화면 구성",
      "ty": "bar",           // bar | ms(마일스톤)
      "st": "run",           // plan | run | done | late | hold
      "og": "다임리서치",     // 담당 조직
      "pg": 20,              // 진척률 0~100
      "dp": ["e2"],          // 선행 일정 id 배열
      "note": ""
    }
  ]
}
```

### 모델 관련 결정 사항

| # | 결정 | 근거 / 영향 |
|---|---|---|
| D-1 | 일정은 **트랙 id를 참조**하고 트랙명을 복사하지 않음 | 트랙명 변경 시 과거 일정이 깨지지 않음 |
| D-2 | 날짜는 **일(日) 단위 정수 인덱스**로 환산해 배치 | 주/월 확대·축소가 배율 변경만으로 성립 |
| D-3 | 종료일은 inclusive | 사용자가 "10/31까지"라고 말하는 방식과 일치 |
| D-4 | 선후행(`dp`)은 **표시 전용**, 자동 일정 재계산 없음 | 자동 밀어내기는 오히려 PM 의도를 훼손 (→ Phase 2에서 "영향 경고"만 추가) |
| D-5 | 상태(`st`)와 진척률(`pg`)은 분리 | 진척 70%인데 지연인 경우가 실제로 존재 |
| D-6 | 트랙 개수·이름은 런타임 편집 대상 | 과제 구조가 연차별로 바뀜 |

## 4. 화면 구성

```
┌ 툴바 ─────────────────────────────────────────────────────┐
│ 로고 · 제목 · 기간표기        [검색][축소/기본/확대][트랙]   │
│                              [되돌리기][테마][인쇄][데이터][+일정] │
├ 상태 요약 바 (상태 우선 원칙) ─────────────────────────────┤
│ ●계획 23  ●진행중 3  ●완료 0  ●지연 0  ▨보류 2 │ 향후 2주 마일스톤 0 │ 조직 필터 칩 │
├ 캘린더 ───────────────────────────────────────────────────┤
│ 월밴드 │ 주 │ 트랙1 │ 트랙2 │ 트랙3 │ … │ +  ← 헤더(sticky) │
│  10월  │10.05│ ┌일정카드┐        ┌카드┐                     │
│        │10.12│ └───────┘  ◆마일스톤                        │
│        │10.19│                                              │
└──────────────────────────────────────────────────────────┘
                                      ▶ 우측 슬라이드 패널(일정편집 / 트랙관리 / 데이터)
```

### 레이아웃 규칙

- **세로축** = 1주 = 1행. 행 구분은 실선(`--border`), 월 경계는 굵은 실선(`--border-bold`).
- **가로축** = 트랙. 트랙 수는 가변. 컬럼 구분선 실선.
- 일정 카드는 `top = 시작일 인덱스 × 일당픽셀`, `height = 기간 × 일당픽셀`로 절대 배치.
- **겹침 처리**: 같은 트랙 내에서 기간이 겹치는 일정끼리만 *클러스터*로 묶어 좌우 분할한다. 겹치지 않는 구간의 일정은 전체 폭을 사용한다. (단순 트랙 전체 분할 방식은 빈 열이 생겨 폐기)
- 클러스터 최대 레인 수가 2 이상인 트랙은 컬럼 폭을 비례 확장(계수 `1 + 0.55 × (레인수 − 1)`, 상한 2.4).
- 마일스톤은 레인 계산에서 제외하고 컬럼 폭 기준 인셋(좌우 12px) 오버레이로 렌더. 그림자로 레이어 구분.
- 오늘 날짜에 Primary 색 기준선 + 날짜 배지.

## 5. 인터랙션 명세

| 동작 | 조작 | 결과 |
|---|---|---|
| 일정 이동 | 카드 드래그 | 상하 = 일 단위 스냅 이동, 좌우 = 트랙 이동. 기간 길이 유지 |
| 기간 조절 | 카드 하단 8px 그립 드래그 | 종료일만 변경. 마일스톤은 무시 |
| 일정 생성 | 빈 셀 더블클릭 / `+ 일정` | 해당 트랙·해당 주에 2주 길이 기본 일정 생성 후 편집 패널 열림 |
| 일정 편집 | 카드 클릭 | 우측 패널. 제목·상태·트랙·유형·기간·병합폭·진척률·담당·선행일정·비고 |
| 일정 삭제 | 패널 `삭제` / 선택 후 `Delete` | 삭제 + 타 일정의 `dp`에서 참조 제거 |
| 트랙 추가 | 헤더 우측 `+` / 트랙 패널 | 맨 뒤에 추가 |
| 트랙 순서·이름·삭제 | 트랙 패널 | 삭제 시 소속 일정 동반 삭제 확인 |
| 필터 | 상태 칩 / 조직 칩 토글 | 비대상 일정 비표시. 레인·컬럼 폭 재계산 |
| 검색 | 상단 검색어 입력 | 비매칭 일정 흐리게(22%), 매칭 일정 Warning 링 강조 |
| 되돌리기 | `Ctrl/⌘ + Z` / 아이콘 | 최대 60단계 스냅샷 복원 |
| 기간 변경 | 데이터 패널 시작·종료일 | 시간축 전체 재생성 |
| 반출/반입 | 데이터 패널 JSON | 복사 / 붙여넣기 적용 |
| 인쇄 | 인쇄 버튼 | 툴바·패널 숨김, 보드 전체 출력 |

### 저장 규칙
- 모든 변경은 즉시 `localStorage`에 반영(디바운스 없음, 문서 크기 수십 KB 수준).
- 변경 직전 상태를 undo 스택에 push. 드래그는 이동 시작 시점에 1회만 push.

## 6. 디자인 준수 사항 — 다임리서치 UI/UX 가이드라인 v1.0

시안은 가이드라인의 **디자인 파운데이션**을 그대로 적용했다. 구현 시에도 아래를 유지한다.

| 항목 | 적용 내용 |
|---|---|
| 색상 토큰 | Primary(50~950), Neutral(Stone, 50~950), Success=Blue-500, Warning=Amber-500, Error=Red-500을 CSS 변수로 선언. **HEX 직접 사용 금지**, 시맨틱 토큰(`--text-primary`, `--border`, `--accent` 등)을 경유 |
| 6:3:1 비율 | Base = Neutral 배경, Contents = Neutral 텍스트·보더, Accent = Primary. **Primary는 CTA·오늘 기준선·진행중 상태에만 사용** |
| 상태 색상 | 계획=Neutral / 진행중=Primary / 완료=Success / 지연=Error / 보류=해치 패턴. 트랙별 임의 색상 부여는 하지 않음 (가이드의 "색상을 정보로 취급" 원칙 준수) |
| 타이포 | Pretendard. text-xs(12/16) = 카드 제목·메타, text-sm(14/20) = 본문·패널, text-base(16/24) = 상단 제목 |
| 단위 | 4px 베이스 그리드. 모든 padding/gap/높이를 `--u1`~`--u10` 토큰에서만 선택 |
| 아이콘 | Lucide 계열, 24px 그리드, 1.5px centered stroke, 인라인 SVG |
| 다크 테마 | 시맨틱 토큰 재매핑으로 지원. 시스템 설정 자동 감지 + 수동 전환 |
| 접근성 | 포커스 링 2px Primary, 텍스트 대비 WCAG AA, `prefers-reduced-motion` 시 패널 트랜지션 제거 |

**미준수/협의 필요 항목**
- 웹폰트: Pretendard를 CDN 스타일시트로 로드하지 못하는 환경이어서 로컬 설치 폰트 → Noto Sans KR → system-ui 순으로 폴백한다. 사내 배포 시 Pretendard 자체 호스팅 필요.
- 가이드라인에 컴포넌트(버튼/패널/칩) 스펙 섹션이 아직 없어 파운데이션에서 파생해 임의 정의했다. 컴포넌트 규격 확정 시 재정렬 필요.

## 8. 기술 메모 (P1 이상 구현 시)

- 렌더링은 DOM 절대 배치 + 인라인 CSS 변수 방식. 일정 200건 수준까지는 전량 재렌더로 충분하다. 그 이상이면 가상 스크롤 대신 **변경 노드만 갱신**하는 방식으로 전환.
- 선후행 화살표는 렌더 직후 `offsetLeft/offsetTop` 기준으로 SVG 경로를 직교 라우팅한다. 리사이즈 시 재계산 필요.
- 날짜 계산은 전부 로컬 타임존 기준 `Date` + 일 단위 정수. UTC 혼용 금지(하루 밀림 발생).
- 데이터 스키마에 `version` 필드를 추가하고 마이그레이션 함수를 두는 것을 P1에서 반드시 선행할 것. 현재 시안은 스키마 검증 없이 JSON을 신뢰한다.

## 9. 검토 요청 사항

1. 트랙 축을 **요구사항 기준**으로 둘 것인가, **WP(작업패키지) 기준**으로 둘 것인가 — 현재 시안은 LG엔솔 요구사항 5종 + 테스트베드 구축으로 구성
2. 상태 5종(계획/진행중/완료/지연/보류)이 과제 보고 체계와 일치하는지
3. 담당 조직 분류를 현재의 5개(다임리서치/다임랩스/에이텍모빌리티/에이텍오토/LG에너지솔루션) + 공동으로 확정할지
4. P1 서버 저장을 별도 개발할지, 사내 기존 시스템에 붙일지
