## 0. 요약 (에이전트용 우선 지침)

화면을 만들 때 아래 7개만 지켜도 가이드라인 위반은 대부분 피할 수 있다.

1. 색상은 **의미 기반 토큰으로 참조**한다. HEX 직접 사용 금지. 팔레트에 없는 색은 임의로 추가하지 않는다.
2. 브랜드 색은 `#F86517`(Primary-500). **CTA·강조 영역에만** 쓴다.
3. 화면 색 면적 비율은 **6(Base/배경) : 3(Contents/텍스트) : 1(Accent/CTA)**.
4. 상태는 색으로 즉시 식별되게 한다. Success=Blue-500, Warning=Amber-500, Error=Red-500.
5. 서체는 **Pretendard** 단일. 크기·행간은 §4 스케일에서만 고른다.
6. 모든 간격·패딩·크기는 **4px 베이스 그리드** 단위 스케일에서만 고른다. 임의 픽셀 금지.
7. 아이콘은 **Lucide**, 24px 그리드, 1.5px centered stroke, SVG.

가이드라인에 없는 케이스는 임의 처리하지 않고 담당자와 협의 후 가이드라인에 추가한다.

## 1. 문서 목적과 사용 방법

### 1.1 목적
다임리서치 웹 제품군 전반에 일관된 사용자 경험을 구현한다. 디자이너와 개발자가 공통의 원칙과 언어로 협업하도록 시각적 체계와 사용성 기준을 정의하고, 유지보수 가능한 디자인 자산을 제공한다. 이를 통해 제품 품질과 신뢰도를 높이고, 고객이 빠르고 정확한 판단을 내릴 수 있는 인터페이스 기준을 세운다.

### 1.2 대상 독자

| 독자 | 참고 범위 | 목적 |
|---|---|---|
| 프로덕트 디자이너 | 전체 섹션 | 시각 기준과 컴포넌트 규격의 전체 맥락 파악 |
| 프론트엔드 개발자 | 디자인 파운데이션, 컴포넌트 | 구현에 필요한 토큰·스펙·상태 기준 확인 |
| 외부 협력사 | 컴포넌트 | 연동 시 준수해야 하는 컴포넌트 규격 확인 |

### 1.3 사용 방법

| 상황 | 절차 |
|---|---|
| 신규 화면 설계 | 디자인 파운데이션(색상/타이포그래피/간격) 기준을 먼저 확인한 뒤 설계 시작 |
| 컴포넌트 구현 | 컴포넌트에 정의된 스펙과 상태를 기준으로 구현 |
| 가이드라인에 없는 케이스 | 임의 처리 금지. 담당자와 협의 후 가이드라인에 추가 |
| 색상 추가 필요 | 팔레트에 없는 색상 임의 사용 금지. 색상 변경 보고서의 토큰 체계를 기준으로 협의 |

### 1.4 버전
| 버전 | 시점 | 내용 |
|---|---|---|
| v1.0 | 2026.03 | 최초 작성 |

## 2. 디자인 전략

### 2.1 목표와 어조
> 모든 공정이 하나의 언어로 연결되는, 신뢰할 수 있는 제어 경험을 만든다.

| 어조 | 구현 방식 |
|---|---|
| 신뢰성 | 정확한 상태 언어(정상 / 경고 / 이상), 정렬된 그리드, 오차 없는 수치 표현 |
| 명확성 | 짧고 직관적인 레이블, 정보 위계 강조, 불필요한 장식 제거 |
| 전문성 | 도메인 약어 존중, 고밀도 데이터의 가독성 확보 |
| 접근성 | 비전문가도 이해 가능한 보조 설명, 색상 대비 확보, 상태 피드백의 즉시성 |

### 2.2 사용자 경험 원칙

| ID | 원칙 | 내용 |
|---|---|---|
| UX-1 | 상태 우선 (Status First) | 화면을 열었을 때 행위나 설정의 상태를 가장 먼저 파악할 수 있어야 한다. 모든 레이아웃은 상태 표시를 최우선 위계로 배치한다. |
| UX-2 | 신뢰 기반 피드백 (Trustworthy Feedback) | 이상 감지·알림·오류 메시지는 **원인 / 위치 / 조치 방법**을 함께 제공한다. 단순한 오류 발생 알림만 하는 것은 허용하지 않는다. |
| UX-3 | 맥락적 밀도 (Contextual Density) | 화면·컴포넌트의 맥락과 필요한 정보 밀도를 감안해 설계한다. 컴포넌트는 단순 모드 / 상세 모드처럼 맥락에 따른 여러 단계·형태를 지원하도록 설계한다. |
| UX-4 | 일관된 확장 (Consistent Scaling) | 동일한 디자인 토큰과 컴포넌트를 공유한다. 제품별·화면별 커스텀은 합의와 승인을 통해 허용된다. |

## 3. 색상 시스템

### 3.1 기존 체계와 개선 배경

**기존 Primary**: `primary-hover #FFA256` / `primary-main #F28C38` / `primary-dark #D4701F`

| 문제 | 내용 |
|---|---|
| 낮은 채도감 | primary-main의 명도가 높아 다크 배경에서 색이 가볍게 보이고, 주색상에 요구되는 선명한 포인트 역할을 못 함 |
| 적은 스케일 | Primary가 3개뿐이라 배지·포커스 링·선택 상태 등에 대응 불가. 컴포넌트가 늘수록 임의 색상 추가가 불가피 |
| 접근성 미검증 | primary-dark의 다크 배경 대비 4.09:1로 WCAG AA(4.5:1) 미달 |

**기존 Grayscale**: `text-primary #FFFFFF`, `text-secondary #A0A6B1`, `border #4A505A`, `bg-input #424751`, `bg-canvas #383C45`, `bg-panel #282C34`, `bg-header #1E2228`

| 문제 | 내용 |
|---|---|
| 불완전한 스케일 | 배경과 텍스트 두 극단에만 집중. 비활성 텍스트·placeholder 등 중간 계층 대응 불가 |
| 색온도 충돌 | Grayscale은 차가운 색온도, Primary는 따뜻한 색온도. 강조 요소가 배경에서 자연스럽게 분리되지 않음 |
| 단계 간격 불균등 | 어두운 색이 특정 명도 구간에 밀집해 구분이 어렵고, 중간 밝기 구간은 비어 있어 토큰 매핑에 제한 |

### 3.2 신규 브랜드 컬러

| 항목 | 값 |
|---|---|
| HEX | `#F86517` |
| RGB | 248, 101, 23 |
| HSL | 21, 94%, 53% |
| OKLCH | 0.6844, 0.1963, 42.6 |

웹사이트 실사용 색상의 계보를 유지하면서 다크 테마에서도 WCAG AA(4.5:1)를 통과하도록 재정의했다.

### 3.3 목적과 원칙

| 구분 | 내용 |
|---|---|
| 목적 | 일관된 시각 언어 확립 — 모든 화면에서 동일한 컬러 원칙 유지 |
| 목적 | 다크 환경 가독성 확보 — 제품 UI 위에서 모든 포인트 컬러가 WCAG AA 이상 대비 유지 |
| 목적 | 상태와 우선순위의 직관적 구분 — **색상을 정보로 취급**. 각 상태는 색으로 즉시 식별 가능해야 함 |
| 원칙 | 일관된 원칙으로 사용 — 일관성과 사용성의 명확함을 함께 고려 |
| 원칙 | **하드코딩 금지** — 의미 기반 토큰 구조로 참조. HEX 직접 사용 금지 |

### 3.6 6:3:1 색상 비율

다임리서치 제품 화면은 6:3:1 비율 원칙을 기반으로 설계한다.

| 비중 | 역할 | 담당 |
|---|---|---|
| 6 | Base, Background | 여백과 안정감 |
| 3 | Contents, Text | 명료한 정보 전달 |
| 1 | Accent, CTA | 사용자의 주의를 자연스럽게 유도 |

이 비율은 색상 시스템을 보조해, 사용자에게 신뢰감과 집중감을 주는 시각적 균형을 만든다.

## 4. 타이포그래피

### 4.1 서체 — Pretendard

디지털 환경의 가독성과 확장성을 우선해 Pretendard를 기본 서체로 사용한다.

| 선정 근거 | 내용 |
|---|---|
| 기존 CI 맥락 유지 | 웹사이트에서 Noto Sans KR로 전달해 온 안정적·정제된 인상을 계승. 고딕 계열 구조라 이질감 없이 연속됨 |
| 디지털 가독성 | 다양한 해상도·플랫폼에서 선명하고 안정적인 렌더링, 다양한 굵기 지원으로 화면 밀도에 유연 대응 |
| 운영 효율 | 오픈소스(OFL), 라이선스 비용 없음, CDN 배포 지원, 폰트 교체 시 시각적 충돌 최소 |

**지원 굵기**: Light(300) / Regular(400) / Medium(500) / SemiBold(600) / Bold(700)

### 4.2 Noto Sans KR 대비

| 구분 | Noto Sans KR (기존 웹사이트) | Pretendard (적용) |
|---|---|---|
| 계열 | 고딕체 / 범용 산세리프 | 모던 산세리프 (고딕 기반 최적화) |
| 특징 | 다국어 지원 중심, 자간 넓음 | 명료한 가독성, 디스플레이 화면 중심 설계 |
| 라이선스 | 오픈소스(OFL), 무료, CDN 배포 | 오픈소스(OFL), 무료, CDN 배포 |

## 5. 아이콘

복잡한 산업 정보를 단순하고 명료하게 시각화하며, 전 제품에서 일관된 시각 언어를 형성한다.
**역할**: 정보 전달 / 조작 유도 / 상태 피드백

| 핵심 원칙 | 내용 |
|---|---|
| 일관성 | 모든 화면·컴포넌트에서 동일한 선 굵기·비율·시각 규칙을 유지해 학습 없이 즉시 인식 |
| 명료성 | 불필요한 장식 없이 핵심 의미만 전달. 소형 아이콘부터 고해상도까지 선명하게 인지 |
| 직관성 | 형태가 기능과 동작을 자연스럽게 암시하도록 설계해 설명 없이 의미 파악 |

| 스펙 | 값 |
|---|---|
| 기준 크기 | 24 × 24 px 그리드 |
| 스트로크 | 1.5px centered stroke |
| 내부 여백 | 2px inner spacing |
| 스타일 | Line-based |
| 리소스 | Lucide icons |
| 형식 | SVG 권장 |

| 톤 | 내용 |
|---|---|
| 시각톤 | 과도한 각짐 없이 자연스럽게 처리된 곡선으로 기술적 정밀함과 접근성을 동시에 전달 |
| 표현톤 | 획 굵기와 여백으로 의미를 완성하고 장식적 요소를 배제해 기능 중심의 산업용 UI 맥락에 부합 |
| 형태톤 | 24px 그리드 위 정렬된 비례로 설계되어 어떤 배경색·크기에서도 시각적 안정감 유지 |

## 6. 단위 및 간격

모든 UI 속성은 **4px 베이스 그리드**에서 파생된 단위 시스템으로 정의된다.

**규칙**
- 모든 간격·패딩·마진·컴포넌트 크기는 이 단위 스케일에서만 선택한다.
- 임의의 픽셀 값은 허용하지 않는다.

### 8.3 상태 색상 적용 규칙

| 상태 | 표면 | 테두리·강조 | 비고 |
|---|---|---|---|
| 기본/비활성 | `neutral-100` | `neutral-300` | 색상을 소비하지 않음 |
| 진행/강조 | `primary-50` | `primary-500` | Accent 1 비중 안에서만 사용 |
| 완료/긍정 | `success-50` | `success-500` | |
| 주의 | `warning-50` | `warning-500` | |
| 오류/파괴적 행동 | `error-50` | `error-500` | 되돌릴 수 없는 액션에 사용 |

다크 테마에서는 `-50` 단계를 그대로 쓰면 밝은 면이 떠 보이므로, 해당 색상의 알파 오버레이(예: 12~18%)로 치환한다.

- [ ] 팔레트에 없는 색을 추가하지 않았는가
