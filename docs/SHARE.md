# 보드 호스팅 — 설계 (2026-10-12 · 1~3단계 구현)

> **구현 메모(2026-10-12).** 설계에서 '호스팅 탭'이라 적은 것은 **호스팅 창**으로 만들었다 — 같은 렌더러를 `?hosting=id`로 띄워
> 참가자 브라우저와 같은 코드 길(HostedAdapter)을 탄다. 탭마다 저장소를 바꿔 끼우지 않아도 된다.
> 파일: `electron/hosting/index.js`(사본·이력·웹 서버·순서), `electron/db/migrations/024_hosting.sql`, `src/core/ops.js`(변경 쪼개기·적용),
> `src/core/merge3.js`(3방향 합치기), `src/core/storage.js` HostedAdapter·IpcHostTransport·HttpTransport, `src/ui/session.js`(공유 화면),
> `src/ui/hosting.js`(시작·목록·거두기). 스모크 `700-hosting`·`710-harvest`.
> 정규화를 변경마다 돌리므로 **정규화는 같은 문서에 몇 번 돌려도 같아야 한다**(포함 관계 id를 다시 만들지 않고 유지 — schema.js).

> 보드 하나를 이 PC(호스트)에서 사내망에 열어, 브라우저로 들어온 사람들과 동시에 보고 고친다.
> **호스팅하는 동안 그 보드는 원래 보드와 떨어진 독립 사본으로 운영되고**, 고친 것을 '거둘' 때 호스트가 합칠지·무엇을 남길지·
> 따로 둘지를 정한다. 호스트는 서버가 아니라 노트북이라 언제든 꺼질 수 있으므로 **사본과 변경 이력은 호스트 DB에 남고, 다시
> 호스팅하면 거기서 이어진다.**

결정(2026-10-12 사용자):

| 항목 | 결정 |
|---|---|
| 운영 | 호스팅 = 보드를 떼어 낸 **독립 사본**. 호스팅 중엔 원래 보드와 서로 영향 없음 |
| 거두기 | 호스트가 판단 — ① 떼어 낸 **원래 보드에 합치기**(3방향, 충돌은 호스트가 고름) ② **독립된 보드로**(새 id, 원래와 남) ③ 버리기 / 계속 호스팅 |
| 합칠 대상 | **떼어 낸 원래 보드만**. 다른 보드로는 ②로 가져온 뒤 항등설정 |
| 이력 | 사본·변경 기록을 호스트 DB에 남긴다. 재호스팅하면 이어서, 거둔 뒤에도 보관 |
| 공개 범위 | **사내망(LAN)만** — 사설 대역이 아닌 곳에서 온 연결은 거절 |
| 입장 | **포트 주소만** — `http://사내 IP:포트/`를 크롬 등 브라우저로 열면 바로. 토큰·이름 입력 없음(이름은 '참가자 N', 막대에서 바꾼다). 처음엔 토큰 링크 + 이름 입력으로 만들었다가 사용자가 '참가자 제약은 두지 않는다'고 바로잡음(2026-10-12) |
| 포트 | 1126부터. 호스팅마다 하나씩 올린다(1127, 1128…). 한 번 받은 포트는 그 호스팅에 기억해 재호스팅 때 같은 주소 |
| 동기화 | 호스트 기준 순서 + 칸 단위 나중 것 우선(아래 §3). CRDT는 쓰지 않는다(비고 글 동시 입력만 나중 선택지) |

## 1. 개념 — 시스템의 말로

호스팅 사본은 **보드가 아니고 이벤트도 새로 만들지 않는다.** 떼어 낸 시점의 보드 문서(투영)를 그대로 들고 있는 *작업 사본*이다.
이벤트 id는 원래 것 그대로 — 거둘 때 "같은 이벤트인가"를 id로만 판단한다(LESSONS 7: 공유는 같은 id일 때만).
사본은 DB의 4대상(`event`·`containment`·`disp`·`rel`)에 쓰지 않는다 — 거두기 전까지 시스템에는 아무 일도 없다.
그래서 런처·그래프·검색·다른 보드 어디에도 사본이 나오지 않는다.

| 화면의 말 | 무엇인가 |
|---|---|
| 호스팅 시작 | 보드 문서를 떼어 사본 + 기준(떼어 낸 시점) 저장, 웹 서버 열기 |
| 호스팅 탭 | 호스트 앱에서 사본을 고치는 탭 ("호스팅 · 보드명 · :1126"). 원래 보드 탭과 따로 |
| 참가자 | 포트 주소로 들어와 사본을 고치는 사람(브라우저) |
| 거두기 | 사본을 원래 보드에 3방향 합치기 / 새 보드로 / 버리기 |
| 호스팅 이력 | 사본 문서 + 변경 기록(누가·언제·무엇) |

## 2. 저장 — 호스트 DB

마이그레이션 024에 두 표를 더한다. 보드에 매인 표시성 표가 아니라 **원래 보드가 지워져도 남아야** 한다(②독립 보드로 거둘 수 있게) —
그래서 `board_id`가 아니라 `source_board_id`(지워지면 NULL, CASCADE 아님). 규약 18의 의도적 예외로 적는다.

```
hosting(id, source_board_id NULL, name, port, token, status, base_json, doc_json, doc_seq, created_at, updated_at, closed_at, result_json)
  status: open(호스팅 중) | paused(꺼짐 — 다시 열 수 있음) | harvested(거둠) | discarded(버림)
  base_json  떼어 낸 시점 문서 — 3방향 합치기의 기준. 바뀌지 않는다
  doc_json   사본의 최근 문서(스냅샷), doc_seq까지 반영
hosting_op(hosting_id, seq, author, at, op_json)   변경 하나 = 한 줄. seq는 호스팅 안에서 1부터
```

- 변경은 **받는 즉시** `hosting_op`에 쓴다(SQLite WAL). `doc_json`은 몇 초·몇십 개마다 스냅샷 — 다시 열 때 스냅샷 + 그 뒤 변경을 다시 적용.
- 노트북이 꺼지거나 앱이 죽어도 마지막으로 받은 변경까지 남는다. 앱을 다시 켜면 `open`이던 호스팅은 `paused`로 보이고, 다시 열면 같은
  포트(같은 주소)로 이어진다.
- 거둔 뒤에도 행과 변경 기록은 지우지 않는다(이력). 지우기는 호스트가 따로.

## 3. 동기화 — 호스트 기준, 칸 단위

### 변경(op)
문서를 고친 것을 **대상 + 칸** 단위로 쪼갠 것. 문서는 정규화되어 대상마다 id가 있으므로 일반 diff로 만든다(`src/core/ops.js`, DOM 모름, 순수).

```
{ k:'item', id, set:{ ti:'…', 'place.x':0.2 } }     칸 고치기(place는 칸마다 따로)
{ k:'item', id, add:{…일정 전체} } / { k:'item', id, del:true }
{ k:'rel'|'track'|'memo'|'band'|'org', id, set|add|del }
{ k:'meta', set:{ 'display.fontScale':1.1, hidden:[…] } }
```
`store.commit` 전후 문서를 diff해 만든다 — 지금의 commit·begin/end 구조를 바꾸지 않는다(규약 2). 끌기는 놓을 때 한 번(이미 begin~end).

### 순서와 충돌
- 호스트(메인 프로세스)가 받은 순서대로 번호(seq)를 붙여 사본에 적용하고 모두에게 뿌린다. Figma가 공개한 방식과 같다 — 서버가 중심에
  있으면 CRDT 없이도 모두 같은 결과로 모인다.
- **같은 칸을 동시에 고치면 나중에 도착한 것이 이긴다.** 다른 칸이면 둘 다 산다(제목과 날짜를 각자 고쳐도 둘 다 남는다).
- 지워진 대상에 온 고치기는 버린다.
- 적용 뒤 `normalize`(schema.js — 메인이 이미 쓴다)로 검사해 **모순을 만드는 변경은 거절**하고 보낸 사람에게 되돌림을 알린다
  (예: 둘이 동시에 서로를 부모로 → 뒤의 것 거절).
- 참가자 화면은 보낸 변경을 먼저 그려 두고(낙관적), 호스트 번호가 붙어 돌아오면 확정. 그 사이 남의 변경이 같은 칸이면 내 것이 뒤라 이긴다.
- 남의 변경은 한 프레임에 모아 한 번만 다시 그린다. 내가 끌거나 글을 쓰는 중이면 그 대상은 끝날 때까지 미뤄 손이 튀지 않게 한다.

### 되돌리기
지금 되돌리기는 문서 스냅샷을 통째로 되살린다 — 공유 중에 쓰면 **남이 고친 것까지 되돌린다.** 호스팅 탭·참가자 화면에서는
'내가 보낸 변경의 반대 변경'을 보내는 방식으로 바꾼다(남의 변경은 건드리지 않는다). 원래 보드 탭은 지금 방식 그대로.

### 전송
`ws` 같은 새 의존성 없이 **SSE(서버 → 화면) + POST(화면 → 서버)**. 사내망이라 지연은 문제되지 않는다.
함께 보기(누가 어느 카드를 고르고 고치는지)는 기록하지 않는 가벼운 신호로 따로 보낸다. 표식은 이름 글자로 — 색은 상태를 뜻하므로
사람마다 색을 주지 않는다(규약 4·7).

## 4. 웹 화면 — 같은 렌더러, 다른 저장소

- 메인 프로세스의 HTTP 서버가 지금 `app://`이 내주는 것과 같은 파일을 내준다 — `index.html`, `src/`, import map이 가리키는
  `node_modules` 패키지, `assets/`, `docs/HELP.md`만. **`electron/`·DB·그 밖은 내주지 않는다.** CSP는 `'self'`라 그대로 맞는다.
- 저장소는 `HostedAdapter`(규약 11) — 사본 문서 받기, 변경 보내기, 받은 변경 적용. 이 아래 코드는 저장 위치를 모른다.
- **참가자 화면에서 막는 것**(DB 전체를 보거나 바꾸는 것 — 열지 않은 보드의 내용이 새지 않게): 런처·다른 보드·탭 추가, 그래프,
  휴지통, 항등설정·조합설정(전체 이벤트 트리를 보여 준다), 다른 보드 참조로 가기, 데이터 창의 반입·이력 되돌리기·초기화, 보드 삭제.
  보이되 고칠 수 없는 것: 다른 보드 이벤트 이름(참조·조합 목록) — 떼어 낼 때 이름만 사본에 같이 담는다.
- 호스팅 탭(호스트)도 같은 제한 — 사본 안에서 항등·조합을 바꾸면 거두기 전에 DB 전체를 건드리게 된다. 그런 일은 거둔 뒤 원래 보드에서.
- 사내망만: 연결한 쪽 주소가 사설 대역(10/8, 172.16/12, 192.168/16, 169.254/16, 루프백, IPv6 fc00::/7·fe80::/10)이 아니면 거절.
  주소는 `http://<호스트의 사내 IP>:<포트>/` — 입장 제약 없음. 참가자 화면인지는 서버가 첫 화면에 넣는 `<meta name="wolfpack-hosting">`로 안다.
  (`hosting.token` 칸은 024에서 NOT NULL이라 채우지만 쓰지 않는다.)
- HTTP라 내용이 암호화되지 않는다 — 사내망 안이라도 미공개 자료가 든 보드는 호스트가 판단해서 연다(회사 AI·보안 지침과 별개로
  제품 안내 문구로 알린다).

## 5. 거두기 — 3방향 합치기

`base`(떼어 낸 시점) · `theirs`(사본) · `ours`(지금 원래 보드) 세 문서를 대상·칸 단위로 비교한다(`src/core/merge3.js`, 순수).

| base→theirs | base→ours | 결과 |
|---|---|---|
| 바뀜 | 그대로 | theirs |
| 그대로 | 바뀜 | ours |
| 같게 바뀜 | 같게 바뀜 | 그 값 |
| 다르게 바뀜 | 다르게 바뀜 | **충돌 — 호스트가 고름** |
| 지움 | 고침 (또는 반대) | **충돌 — 호스트가 고름** |
| 새로 만듦 | — | 더함 |

- 충돌 목록: 대상(카드 제목)·칸·양쪽 값·사본 쪽을 고친 사람. 칸마다 고르거나 "전부 사본 쪽 / 전부 보드 쪽", 사람별 일괄.
- 합친 문서는 **지금 저장 경로 그대로** 원래 보드에 쓴다(`repo.save`, 보드가 본 것만 고친다 — SAVE.md). 사본에서 지운 카드는 '보드에서
  빼기'이지 이벤트 삭제가 아니다. 같은 이벤트가 다른 보드에도 놓여 있으면 본질(제목·날짜) 변경은 그 보드에도 보인다 — 지금 공유 이벤트를
  고칠 때와 같다. 거두기 화면에 "다른 보드에도 있는 일정 N개가 함께 바뀝니다"를 알린다.
- ② 독립된 보드로: 사본을 `reidentify`(새 id 전부)해 새 보드로 만든다 — 원래 보드와 남.
- 거두기는 되돌리기 1단계 + DB 백업 먼저(LESSONS 8). 결과 요약을 `hosting.result_json`에 남긴다.

## 6. 호스트 화면

- 보드 도구 모음 **호스팅** — 확인 후 호스팅 창이 뜬다. 방화벽 허용은 Windows가 처음 한 번 묻는다.
- 호스팅 창 위쪽 막대: 주소 복사, 참가자 목록(이름·보기 전용/편집·내보내기), 이력, 호스팅 멈춤. 참가자 막대엔 '내 이름'.
- 첫 화면(런처)에 **호스팅** 칸: 호스팅마다 상태(호스팅 중 / 꺼짐 / 거둠 / 버림)·원래 보드·변경 수·마지막 변경 시각. 다시 열기 · 거두기 ·
  이력 보기(누가·언제·무엇) · 버리기.

## 7. 단계

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1 | DB 024, 떼어 내기·멈춤·다시 열기, HTTP 서버(파일 + SSE + POST, 사내망만), 참가자 **보기 전용**, 호스팅 창, 런처 호스팅 칸 | 브라우저 둘이 같은 사본을 보고, 호스트가 고치면 바로 보인다. 앱을 껐다 켜도 이어 열린다 |
| 2 | `ops.js`(diff·적용), 호스트 순서·검사·거절, 참가자 편집, 낙관적 반영, 내 변경만 되돌리기, 함께 보기, 막는 기능 | 둘이 같은 카드의 다른 칸·같은 칸을 동시에 고쳐도 모두 같은 결과. 이력에 사람별로 남는다 |
| 3 | `merge3.js`, 거두기 화면(충돌 고르기), 원래 보드에 합치기 / 독립 보드로 / 버리기, 이력 보기 | 사본과 원래 보드를 각자 고친 뒤 거두면 표대로 합쳐지고 충돌만 묻는다 |
| (나중) | 비고 글 동시 입력(Yjs 텍스트), 외부망(HTTPS·인증) | 필요해지면 |

각 단계는 스모크 단계로 검사한다 — 메인이 숨은 참가자 창(`http://127.0.0.1:1126/`)을 하나 더 띄워 호스트 창과 번갈아 고치고 결과가
같은지, 참가자가 막힌 기능·DB에 닿지 못하는지, 앱을 다시 띄워 이어지는지. 실제 DB 복사본(`--repro`)으로 떼어 내기·거두기 왕복도.

## 8. 아직 열어 둔 것

- 호스팅 중인 보드를 호스트가 원래 탭에서 계속 고치는 것은 막지 않는다(독립 운영) — 그만큼 거둘 때 충돌이 늘 뿐이다.
- 한 보드를 동시에 두 번 호스팅하는 것은 막는다(한 보드에 열린 호스팅 하나). 거둔 뒤에는 다시 떼어 낼 수 있다.
- 참가자 권한(보기 전용으로 들이기)은 입장 제약이 없어 호스트가 들어온 뒤 바꾼다 — 기본은 편집.
