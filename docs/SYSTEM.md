# 순서 기반 이벤트 전개 시스템 — 본질과 표현 (기준 문서)

> 이 문서가 코드보다 우선한다. 개념이 헷갈리면 여기로 돌아온다.
> 이 문서로 답이 나오지 않으면, **스스로 해석하지 말고 묻는다.**

가장 흔한 오류: 화면에서 보이는 말(보드·트랙·카드·태스크·**동일·조합·별칭**)을 그대로
시스템 개념으로 옮기는 것. **화면의 말은 시스템 개념이 아니다.** 아래 번역표로 옮긴다.

## 화면의 말 → 시스템의 말 (번역표 — 항상 여기부터)

| 화면의 말 | 시스템에서 무엇인가 | 층 |
|---|---|---|
| 보드 | 펼친 이벤트 | 표현 (본질은 이벤트) |
| 트랙 | 하위 이벤트를 한 갈래로 묶어 보여 주는 이벤트 | 표현 (본질은 이벤트 + 포함) |
| 카드 | 순서축 위에 접힌 이벤트 | 표현 (본질은 이벤트 + 순서 있는 포함) |
| 하위 카드 | 카드 안에 순서 있는 포함으로 놓인 이벤트 | 표현 (이벤트 + 순서 있는 포함) |
| 태스크 | 카드 안에 순서 없는 포함으로 담긴 이벤트 | 표현 (이벤트 + 순서 없는 포함) |
| 화살표 | 선행·합류·원인·참조 관계 | 관계 |
| 안에 들어 있다 | 포함 | 관계 |
| 여러 보드에 있다 | 한 이벤트, 여러 포함, 여러 배치 | 관계 + 표현 |
| **조합 · 묶음** | **여러 이벤트로 한 이벤트가 이루어짐** — 대상들을 순서 없이 *구성*으로 포함 (보드가 트랙들의 조합인 것과 같다). 태스크와 다르다(§7.1) | 이벤트 + 관계(포함) |
| **동일** | **두 이벤트를 하나로 합치는 작업** (결과는 이벤트 하나) | 작업 |
| **별칭** | 특정 배치에서만 보이는 이름 | 표현 |
| 트랙 여러 칸에 걸친 카드 | 여러 트랙에 동시 소속, 또는 여러 트랙을 포함하는 이벤트 | 관계 (걸쳐 그리는 것은 표현) |
| 트랙 좌우 순서 | 의미 없음 | 표현 |
| 화면상 위아래 위치 | 순서상 위치의 표시 | 표현 |
| 날짜·달력 | 이벤트의 선택 속성 + 순서축 위 눈금 | 이벤트 + 표현 |
| 마일스톤 | 기간이 없는 이벤트 | 표현 (본질은 이벤트) |
| 보드에서 지우기 | 포함과 배치 제거 | 관계 + 표현 |
| 이벤트 삭제 | 이벤트와 연결된 모든 관계·배치 제거 | 이벤트 |
| 메모(포스트잇) | **시스템에 없다** — 그 보드 화면에 붙인 글. 이벤트도 관계도 아니다 | 표현 (보드 표시 값) |
| 자식 숨기기(모자관계설정의 눈) | 포함은 그대로, 그 보드에서 그리지 않을 뿐 | 표현 (보드 표시 값) |

**금지:**
- 표현층 단어로 이벤트 종류를 만들지 않는다 — "트랙 객체", "태스크 객체"는 없다.
- 표현층 단어로 관계 종류를 만들지 않는다 — **"동일 관계", "조합 관계"는 없다.**
- 표현층 값을 이벤트 본질에 넣지 않는다 — 위치·폭·별칭은 이벤트 속성이 아니다.

## 세 개의 층

| 층 | 묻는 것 | 들어가는 것 |
|---|---|---|
| 이벤트 | 무엇이 있는가 | 이벤트 하나하나와 그 본질 속성 |
| 관계 | 이벤트 사이에 무엇이 있는가 | 포함, 선행, 합류, 원인, 참조 |
| 표현 | 어떻게 보이는가 | 보드, 트랙, 카드, 태스크, 위치, 폭, 정렬, 별칭, 접힘/펼침, 달력 눈금 |

**판정 기준: 화면을 전부 지워도 남는 것은 이벤트와 관계(본질), 화면과 함께 사라지는 것은 표현.**

## 이벤트 (§3)

- 시스템의 **유일한 단위**. 전역 유일 id + 본질 속성(제목·상태·담당·진척·비고·선택적 날짜).
- 본질 판단 질문: "이 값은 **어느 보드에서 보든 같아야 하는가?**" 같아야 하면 본질, 달라도 되면 표현.
- 이벤트가 **가지지 않는 것**: 어느 보드/트랙에 속하는지, 부모가 누구인지, 위치·폭·정렬, 별칭.
  이것들은 전부 관계이거나 표현이다.
- 이벤트는 **보드 밖**에 있다. 보드가 사라져도 이벤트는 남는다. "보드에서 빼기" ≠ "이벤트 삭제".
- 날짜는 본질이되 **선택**. 없어도 관계만으로 자리를 잡는다. 기간 없는 한 시점도 이벤트(마일스톤은 표현 차이).

## 관계 (§4) — 다섯 가지뿐

| 관계 | 뜻 | 구조 규칙 |
|---|---|---|
| 포함(순서 있음) | A 안에 B, B는 A의 순서축 위 | 다중 소속·다단 중첩 허용, **순환 금지(DAG)** |
| 포함(순서 없음) | A 안에 B, 순서축 없이 담김 | 다중 소속 허용, 순환 금지 |
| 선행 | A가 끝나야 B 시작 | 순환 금지 |
| 합류 | 여러 이벤트가 하나로 모임 | 한 이벤트는 합류 대상을 **하나만**(트리) |
| 원인 | A 때문에 B | 순환 금지 |
| 참조 | A가 B를 참고 | 순환 허용 |

- 관계는 이벤트와 **동등한 독립 대상**. 보드를 넘나들고, 어느 보드에도 속하지 않는다.
- **새 관계 종류를 임의로 추가하지 않는다.** 기존 다섯으로 표현되지 않을 때만, 먼저 **묻는다.**
- 순서는 **부분순서** — 선행으로 이어진 것 사이에만 앞뒤가 있다. 화면 위아래는 표시일 뿐.

## 포함: 모든 "안에 있다"는 하나다 (§5)

- 보드 안의 트랙, 트랙 위의 카드, 카드 안의 하위 카드/태스크, 묶은 이벤트 — **전부 포함 하나**.
- 포함은 트리가 아니라 **DAG**: 한 이벤트가 여러 부모를 가질 수 있고(다중 소속), 부모·자식이
  서로 다른 보드에 있어도 된다. **순환만 금지.**
- **"안에 있다"를 두 번 적지 않는다.** 트랙도 이벤트다. 어떤 이벤트가 트랙 위에 있다는 것은
  곧 그 트랙이 부모라는 뜻. "어느 트랙"과 "어느 상위 이벤트"를 따로 적으면 반드시 어긋난다.
- 포함 하나 안에서 담기는 방식은 셋으로 **구분해서 관리한다**(저장: [SAVE.md](./SAVE.md) §5). 새 관계 종류가 아니다.
  - 순서 있는 포함 — 트랙 위 카드, 하위 카드 (부모의 순서축 위)
  - 순서 없는 포함 — 태스크 (이벤트 안의 하위 이벤트가 순서를 갖지 않을 뿐)
  - 구성 — 조합 (여러 이벤트로 이 이벤트가 이루어짐. **보드 → 트랙**도 구성이다)
  - 한 쌍(부모, 자식) 사이에 담기는 방식은 하나다.

## 표현 — 역할 이름 (§6)

보드·트랙·카드·태스크는 이벤트의 **종류가 아니라 포함 관계 안에서의 위치를 부르는 이름**이다.
하나의 이벤트가 동시에 여러 역할(여기선 카드, 펼치면 보드, 저기선 트랙, 또 다른 카드 안 태스크)을 가진다.

- **하위 카드 vs 태스크의 유일한 기준: 순서축 위에 놓이는가.** 위 = 하위 카드, 아니면 태스크.
  태스크에 선행이 생기면 반드시 하위 카드로 전환. 태스크 목록의 나열 순서는 관계가 아니다.
- **배치(placement)**: 이벤트가 특정 포함 관계 위에 놓인 모습. 표현층. (어느 포함 edge 위인가,
  순서 위치, 가로 위치·폭·정렬·접힘, **별칭**.) 별칭은 이벤트 이름을 바꾸는 게 아니라 그 자리에서만
  다르게 보이는 것. 별칭을 둘지는 UI 결정이며 이벤트·관계 구조를 바꾸지 않는다.
- 달력은 순서축 위에 얹는 눈금(표현). **순서상 위치를 먼저 구하고**, 눈금이 켜진 보드에서만 날짜로 환산.

## 작업 → 층 번역 (§7)

| 작업 | 이벤트 | 관계 | 표현 |
|---|---|---|---|
| 이벤트 만들기 | 새 이벤트 | 포함 생성 | 배치 생성 |
| 다른 보드에도 올리기 | 없음 | 새 부모와 포함 추가 | 배치 추가 |
| 보드에서 빼기 | 없음 | 그 포함 제거 | 그 배치 제거 |
| 이벤트 삭제 | 제거 | 연결 관계 전부 제거 | 모든 배치 제거 |
| 카드 다른 트랙으로 | 없음 | 부모 변경 | 배치 변경 |
| 태스크↔하위 카드 | 없음 | 포함의 순서 유무 변경 | 순서축 배치 변경 |
| 트랙/카드로 보기 | 없음 | 없음 | 표현만 |
| **여러 이벤트 묶기(조합)** | **새 이벤트 생성** | **새 이벤트가 대상들을 포함** | 새 이벤트 배치 |
| 묶음 풀기 | 묶음 이벤트 제거 | 묶음의 포함 제거 | 묶음 배치 제거 |
| **동일 매핑** | **두 이벤트를 하나로** | 양쪽 관계를 하나로 모음 | 배치는 그대로, 한 이벤트의 배치가 됨 |
| **항등 해제(분리)** | **한 보드의 놓임을 새 이벤트로** (안쪽도 복제) | 그 보드의 포함을 새 이벤트로 옮김, 관계는 보이는 보드별로 | 그 보드의 배치가 새 이벤트의 배치가 됨 |
| 별칭 붙이기 | 없음 | 없음 | 그 배치에만 이름 표시 |

**삭제 원칙:** 보드/트랙 지우기 = 포함·배치 제거. 안의 이벤트까지 지우는 건 **명시 요청 시에만**.
부모를 모두 잃은 이벤트도 이벤트로 남는다.

### 묶기(조합) — §7.1
"X는 A와 B의 조합"은 **새 관계가 아니라 X가 A·B를 포함**한다는 뜻. 보드-트랙 관계와 같은 구조.
A·B는 원래 자리에도, X에도 소속(다중 소속). **트랙 둘을 합치는 게 아니라, 둘을 품는 이벤트를 새로
두는 것.** A·B는 각자 정체성을 유지한다.

**조합 ≠ 태스크 (2026-09-28, 사용자 정의).** 둘 다 순서가 없는 포함이지만 본질적으로 다르다.
> (원문) 시스템에서 본질적으로 달라 조합과 태스크는. 조합은 정확히 두 이벤트로 하나의 이벤트가
> 만들어진 것이고, 태스크는 이벤트 안에 있는 하위 이벤트들이 순서를 가지지 않을 뿐이야. 보드-트랙
> 관계를 생각해. 모든 이벤트들은 어느 트랙에건 속하자나 특정 보드에서. 보드는 트랙의 조합이라 생각할
> 수 있고. 그런데 태스크를 모은다고 이벤트가 되지 않지. 태스크도 당연히 다른 곳에 속할 수도 있어.
> 복수관계는 항상 허용이자나.

- 조합은 **둘 이상**의 이벤트로 이룬다. 새 이벤트를 만들 때 기존 이벤트들을 조합할 수도 있고, 기존
  이벤트를 다른 이벤트들의 조합으로 정의할 수도 있다.
- 대상은 **다른 보드의 이벤트**다. **같은 보드의 이벤트와의 조합은 모순**이다 (2026-09-28 사용자 정의):
  > (원문) 조합이라면 포함 관계의 일종이고 포함 안에서 트랙이 되는 관계인데, 같은 보드 안에 있는
  > 이벤트들은 명시적으로 관계 설정을 안 했더라도 시스템적으로는 이미 그래프 관계인 거지. 따라서 조합
  > 설정을 눌렀는데, 현재 카드가 속해 있는 보드의 이벤트들은 나타나서는 안 돼. 설정할 수 있게 해서도 안 돼.

  그래서 현재 보드의 이벤트(트랙·카드·태스크, 합치기로 이 보드에도 놓인 것 포함)는 고르기 트리에 나오지
  않고, 정규화·저장도 그런 조합을 받아들이지 않는다. 그 밖에 자기 자신·순환(자기 조상)도 막는다.
- 화면에 어떻게 보일지는 표시 지시를 따른다(지금: 보드에 카드로 그리지 않고 상세에서 보인다). 데이터에서는
  태스크와 반드시 구분해 둔다.

### 동일 매핑 — §7.2
서로 다르게 만든 두 이벤트가 나중에 같은 것으로 밝혀지면 **하나로 합치는 작업**(관계 아님).
- 매핑 전: A(보드1 배치), B(보드2 배치) — 별개. 매핑 후: **이벤트 하나, 배치 둘.**
- 결과는 **처음부터 다중 소속으로 만든 것과 구별되지 않아야** 한다. "동일" 선으로만 잇고 본질을
  따로 두면(동기화만) 안 된다 — 한쪽을 바꿔 다른 쪽이 안 따라오면 동일이 아니다.
- 처리할 것:
  - **본질 충돌**: 제목·상태·날짜가 다르면 하나를 남긴다(사용자 선택/규칙). 다른 이름은 배치 별칭으로 보존 가능.
  - **관계 합치기**: 양쪽 관계를 한 이벤트로 모은다. 그 결과 자기 순환(A가 B를 선행/포함했던 경우)이나
    다른 구조 규칙 위반이 생기면 **매핑을 거부**한다.
  - **사라지는 id**: 없어지는 id를 가리키던 곳이 깨지지 않게 남은 쪽으로 잇는다.
  - **되돌리기**: 합치기 전 두 이벤트 상태를 기록해 나중에 풀 수 있게.

- **트랙 ↔ 보드** (2026-10-08 사용자 정의): 트랙과 보드(루트)를 합치면 한 노드가 된다. 그 노드에서 **1세대 자식이 바로 갈라진다** —
  트랙 쪽 카드(순서 있는 포함)와 보드 쪽 트랙(구성)은 형제일 뿐 서로 잇지 않는다(사용자가 매핑하지 않는 한). 각 자식이 다시 제 가지의
  뿌리다. 그래서 그 보드는 원래 트랙만, 다른 보드의 그 트랙은 원래 카드만 보인다(보드의 트랙 = 루트의 구성 자식, 트랙의 카드 = 순서
  있는 포함 자식). 그 보드를 지우면 루트(다른 보드의 트랙이기도 함)는 남기고 보드 쪽 가지만 지운다.

### 항등 해제(분리) — §7.3
동일 매핑의 반대 작업: 여러 보드에 함께 놓인 **한 이벤트**를, 한 보드에서 **다른 이벤트로 떼어 낸다**(2026-10-01 사용자 결정).
- **그 보드의 놓임**(그 보드 화면의 루트·트랙·카드에서 이 이벤트로 오는 포함)이 새 이벤트로 간다. 본질은 복사한다. 다른 보드는
  원래 이벤트를 그대로 쓴다. 그 보드 밖에서의 놓임이 없으면(다른 보드엔 상위 카드를 통해서만 보이면) 떼어 낼 것이 없다 — 거부.
- **안에 든 것**(순서 있는·없는 포함 — 하위 카드·태스크)은 함께 **복제**해 완전히 별개가 된다. 조합(구성) 대상은 복제하지 않고
  새 쪽도 품는다(대상은 다른 보드의 것이다).
- **관계**는 보이는 보드별로 나눈다: 그 보드에서만 보이던 것은 새 쪽으로 옮기고, 다른 보드에서만 보이던 것은 원래 쪽에 두고,
  양쪽에서 보이던 것은 양쪽에 하나씩.
- 되돌리기: 만든 이벤트를 지우고 옮긴 놓임·관계를 원래대로(repository.unsplitEvent).
