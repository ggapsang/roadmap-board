# WOLFPACK 보드 JSON 읽는 법 (LLM용)

> **쓰는 법** — 이 문서 전체를 프롬프트 앞에 붙이고, 그 뒤에 WOLFPACK에서 반출한 JSON(**데이터 › JSON 반출** 또는
> **복사**)을 붙인 다음 질문을 적는다. 이 문서는 사람이 아니라 AI 모델이 읽도록 쓴 설명이다.

---

## 0. 한 줄 요약

이 JSON은 **프로젝트 일정 보드 하나**다. 세로축은 시간(날짜), 가로는 병렬로 나눈 **트랙**(작업 갈래)이고, 각
**일정(item)** 은 한 트랙 위에 놓인 기간 또는 시점이다. 일정 사이에는 **선행**(A가 끝나야 B) 화살표와 **포함**
(A 안에 B) 관계가 있다.

## 1. 먼저 알아 둘 규칙

1. **id는 불투명한 문자열이다.** `2:e1`, `track:2:t0`, `emujgxwg5gs`처럼 모양이 제각각이다. 접두사나 숫자에서
   의미(순서·보드 번호 등)를 추론하지 말고, 같은 문자열이면 같은 것으로만 본다.
2. **날짜는 `YYYY-MM-DD` 로컬 날짜다.** 시간·시간대는 없다. **종료일(`e`)은 그날을 포함한다** —
   `s: 2026-10-01, e: 2026-10-03`은 3일짜리다. 일수 = `e − s + 1`.
3. **본질과 화면 배치를 구분한다.** 일정의 제목·날짜·상태·담당·진척·비고는 **본질**(어느 보드에서 보든 같다).
   `place` 안의 값은 **이 보드 화면에서의 배치**(위치·폭·색 등)라, 일정의 의미를 판단할 때는 대부분 무시해도 된다.
4. **화면 위아래 위치는 순서가 아니다.** 일의 앞뒤는 **날짜**와 **선행 관계(`dep`)** 로만 판단한다.
5. 이 파일에 **없는 id**가 나오면(주로 `compose`) 그것은 **다른 보드의 이벤트**다. 이 파일에는 그 제목이 없다 —
   "다른 보드의 이벤트(id …)"라고만 말하고 내용을 지어내지 않는다.

## 2. 최상위 구조

```jsonc
{
  "version": 22,          // 문서 형식 버전(해석에는 무시해도 된다)
  "meta":      { ... },   // 보드 이름·표시 기간·표시 설정
  "orgs":      [ ... ],   // 담당 조직 이름 목록
  "tracks":    [ ... ],   // 트랙(가로 칸) 목록 — 배열 순서 = 화면 왼쪽→오른쪽
  "items":     [ ... ],   // 일정 목록 — 이 보드의 핵심
  "relations": [ ... ],   // 일정 사이 관계 — 선행(dep)·포함(contain)
  "compose":   [ ... ],   // 조합(구성) — 이 보드의 일정·트랙이 어떤 이벤트들로 이루어졌는가
  "bands":     [ ... ]    // 왼쪽 달력 칸을 묶거나 높이를 바꾼 것 — 화면 전용, 무시해도 된다
}
```

## 3. `meta` — 보드 정보

| 필드 | 뜻 |
|---|---|
| `name` | 보드(프로젝트) 이름 |
| `start`, `end` | 보드에 선언한 표시 기간(날짜). 일정이 이 밖에 있을 수도 있다 — 기간 밖 일정도 유효하다 |
| `statusLabels` | (있으면) 상태 코드의 이 보드 전용 이름. 예 `{"run":"진행"}` — 아래 §5 상태 표를 덮어쓴다 |
| `display` | 화면 설정. 대부분 무시. 단 **`display.dated === false`면 날짜 없는 보드**다(§6) |

## 4. `tracks` — 트랙(가로 칸)

```jsonc
{ "id": "track:2:t0", "lab": "테스트베드", "name": "테스트베드 구축", "w": 175,
  "s": "2026-09-21", "e": "2027-04-04", "note": "", "alias": null, "fill": null }
```

- `name`: 트랙 이름(작업 갈래). `lab`: 이름 위에 붙는 작은 분류 라벨(비어 있을 수 있다). `w`: 화면 폭 — 무시.
- `s`, `e`: 트랙의 기간(날짜, 없을 수 있다). **보드 기간(`meta.start`~`meta.end`)과 같으면 따로 정하지 않은 것**이다 — 트랙을
  만들 때 보드 기간이 들어간다. 다를 때만 그 갈래의 기간으로 읽는다.
- `note`: 트랙(갈래)에 대한 비고 — 마크다운 글. `alias`: 이 보드에서만 보이는 다른 이름(있으면 화면엔 이것이 보인다). `fill`: 화면 색 — 무시.
- 트랙에 고정된 의미는 없다(요구사항·작업 패키지·조직 등 사용자가 정한 대로). 이름으로 판단한다.

## 5. `items` — 일정

```jsonc
{
  "id": "2:e1",
  "ti": "컨셉 레이아웃 작성",   // 제목 (줄바꿈 \n이 있을 수 있다)
  "s": "2026-09-22",            // 시작일
  "e": "2026-10-20",            // 종료일(그날 포함)
  "ty": "bar",                  // bar = 기간 일정, ms = 마일스톤
  "st": "run",                  // 상태 코드 — 아래 표
  "og": "에이텍모빌리티",        // 담당 조직 (orgs 중 하나)
  "pg": 40,                     // 진척률 0~100 (%)
  "note": "",                   // 비고 — 마크다운 글(목록·체크박스·링크 등이 있을 수 있다)
  "parent": null,               // 상위 일정 id — 있으면 그 일정 **안에** 든 하위 일정
  "alias": null,                // 이 보드에서만 보이는 다른 이름(있으면 화면엔 이것이 보인다)
  "tasks": [ { "id": "k1", "text": "레퍼런스 수집", "done": true } ],  // 할 일 체크리스트
  "place": {                    // ── 이 보드 화면에서의 배치 ──
    "t": "track:2:t0",          // 놓인 트랙(홈 트랙) id
    "tracks": ["track:2:t0", "track:2:t1"],  // 걸쳐 있는 트랙들(여러 트랙에 동시에 속한다)
    "slot": null,               // 날짜 없는 보드에서의 칸 위치(§6). 날짜 있는 보드는 null
    "sp": 2, "x": 0, "w": 1.98, "hd": 27, "oy": null, "fs": null, "align": "middle", "showNote": false, "fill": null  // 화면용 — 무시
  }
}
```

**상태 코드(`st`)** — `meta.statusLabels`가 있으면 그 이름을 쓴다.

| 코드 | 기본 이름 | 뜻 |
|---|---|---|
| `plan` | 계획 | 아직 시작 전 |
| `run` | 진행중 | 진행 중 |
| `done` | 완료 | 끝남 |
| `late` | 지연 | 늦어지고 있음(사용자가 표시한 것) |
| `hold` | 보류 | 멈춤 |

**마일스톤(`ty: "ms"`)** — `s === e`면 한 시점(예: 전시회 개막일, 산출물 제출일), `s < e`면 기간이 있는 마일스톤.

**하위 일정** — `parent`가 있으면 그 상위 일정 안에 든 세부 일정이다. 하위 일정은 여러 단계로 중첩될 수 있다.
같은 정보가 `relations`의 `contain`으로도 한 번 더 들어 있다(§7).

**태스크(`tasks`)** — 일정 안의 할 일 목록. 순서는 의미 없다. `done`이 체크 여부.

**트랙 소속** — 최상위 일정(`parent`가 없는 것)은 `place.tracks`의 트랙들에 속한다(보통 하나, 여러 개면 여러 갈래에
걸친 일). 하위 일정은 상위 일정의 트랙을 따른다.

## 6. 날짜 없는 보드 (`meta.display.dated === false`)

일정에 날짜가 없고(`s`, `e`가 `null`), 순서만 있다. 위치는 `place.slot = { "s": 칸 번호(0부터), "len": 칸 수 }`다.
칸 번호가 작을수록 앞이다. 칸은 날짜가 아니므로 날짜로 바꿔 말하지 않는다("3번째 칸부터 2칸").

## 7. `relations` — 일정 사이 관계

```jsonc
{ "id": "2:r_e21_e20", "type": "dep",     "from": "2:e20", "to": "2:e21" }
{ "id": "rmuncw9pobs", "type": "contain", "from": "2:e10", "to": "2:e11" }
{ "id": "rmv1a2b3c4d", "type": "ref",     "from": "2:e1",  "to": "board:1" }
```

| `type` | 읽는 법 | 규칙 |
|---|---|---|
| `dep` (선행) | **`from`이 끝나야 `to`를 시작한다.** 화면의 화살표 | 순환 없음 — 선행 사슬로 앞뒤·임계 경로를 따질 수 있다 |
| `ref` (참조) | **`from`이 `to`를 참고한다.** 방향 없이 잇는 선으로 보인다 | 순환 허용. 한쪽 끝만 이 보드에 있으면 된다 — 다른 쪽은 다른 보드의 이벤트(카드·트랙·태스크)나 **보드 자체**일 수 있다(id가 이 파일에 없을 수 있다, §1-5) |
| `contain` (포함) | **`from` 안에 `to`가 들어 있다** — `to` 일정의 `parent`가 `from`이다 | 순환 없음. `items[].parent`와 같은 정보 |

- 선행은 **부분순서**다. 선행으로 이어지지 않은 두 일정 사이에는 (날짜 말고는) 앞뒤가 없다.
- `from`/`to`가 이 파일의 `items`에 없는 id라면 다른 보드의 이벤트다(§1-5).

## 8. `compose` — 조합(구성)

```jsonc
{ "parent": "track:1:tmue8yquo5u", "child": "track:2:t3" }
```

- **`parent`는 `child`들로 이루어져 있다**(여러 이벤트가 모여 한 이벤트를 이룬다). 예: 이 보드의 트랙 하나가 다른
  보드의 트랙·일정 여럿으로 구성됨.
- `parent`는 이 보드의 일정이나 트랙이고, `child`는 보통 **다른 보드**의 이벤트라 이 파일에 제목이 없다.
- 하위 일정(`contain`)이나 태스크와 다르다 — 순서가 없고, 화면에 카드로 그리지 않는다.

## 9. 무시해도 되는 것 (화면 전용)

`bands` 전체, `meta.display`(단 `dated`는 §6. `slotRows`도 칸 높이일 뿐), `meta.arrows`(사용자가 고친 화살표 모양), `tracks[].w`·`tracks[].fill`, `place`의 `sp`·`x`·`w`·`hd`·`oy`·`fs`(글자 크기)·`align`·`showNote`·`fill`.
이 값들은 칸 높이·카드 폭·색 같은 **보이는 모양**일 뿐, 일정의 의미·순서·기간과 무관하다.

## 10. 자주 하는 계산

- **기간(일수)**: `e − s + 1`. 영업일이 필요하면 따로 말한다(데이터에 휴일 정보는 없다).
- **특정 날짜에 진행 중인 일**: `s ≤ 날짜 ≤ e`.
- **다가오는 마일스톤**: `ty === "ms"`이고 `s`가 기준일 이후인 것, `s` 순.
- **선행 사슬(먼저 끝나야 할 일)**: `to === X`인 `dep`의 `from`을 거슬러 올라간다.
- **일정이 선행보다 먼저 시작하는 모순**: `dep`의 `to.s < from.e`(겹치거나 앞섬)면 점검 대상이다.
- **담당 조직별·트랙별 묶기**: `og`, `place.tracks`(하위 일정은 상위의 트랙).
- **진척 요약**: `pg`(%)와 `tasks`의 `done` 비율. 상태 `late`·`hold`는 따로 짚는다.
- **오늘 기준 판단**: 이 데이터에는 "오늘"이 없다 — 질문에 기준일이 없으면 기준일을 물어보거나 가정을 밝힌다.

## 11. 답할 때

- 일정은 **제목(`ti`)으로** 부르고, 필요하면 날짜를 곁들인다. id는 사용자가 원할 때만 보인다.
- `alias`가 있으면 "별칭(원래 제목)"처럼 둘 다 보여 준다.
- 파일에 없는 것(다른 보드 이벤트의 제목, 휴일, 인원·비용)은 지어내지 않는다.
