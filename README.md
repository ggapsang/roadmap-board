# Roadmap Board

Project Machina 1차년도 실행계획을 **시간축 위에 정렬된 상태로** 편집·공유하는 데스크톱 보드.

구글 캘린더 주간 화면의 인지 모델을 그대로 쓴다 — 세로는 시간, 가로는 병렬 트랙.
PPT 도형으로 관리하던 일정을 옮겨, 주간 갱신과 선후행 추적이 가능하게 하는 것이 목적이다.

> 공수·원가·리소스 배정·결재는 범위 밖이다. 이 도구는 **보고·합의용 시각화 보드**이며 PMS를 대체하지 않는다.

## 실행

```bash
npm install
npm start
```

Electron 앱이 뜨고, 데이터는 SQLite 파일 하나에 자동 저장된다.

| 명령 | 설명 |
|---|---|
| `npm start` | 앱 실행 |
| `npm run dev` | 개발자 도구를 함께 연다 |
| `npm test` | 스모크 — 창을 띄워 렌더와 저장 왕복을 확인하고 종료 |
| `npm start -- --db ./machina.db` | DB 파일을 직접 지정 (과제별로 나눠 쓸 때) |

DB 기본 위치는 `%APPDATA%/roadmap-board/roadmap.db` — 메뉴의 **파일 › DB 파일 위치 열기**로 바로 갈 수 있다.

## 쓰는 법

| 하고 싶은 것 | 조작 |
|---|---|
| 일정 옮기기 | 카드를 끈다. 위아래는 날짜, 좌우는 트랙 |
| 기간 늘리기 | 카드 아래쪽 가장자리를 끈다 |
| 일정 만들기 | 빈 칸을 더블클릭하거나 툴바 **+ 일정** |
| 일정 고치기 | 카드를 클릭하면 우측 패널이 열린다 |
| 트랙 추가·순서·삭제 | 툴바 **트랙**, 또는 헤더 오른쪽 **+** |
| 상태·조직으로 거르기 | 상단 요약 바의 칩을 누른다 |
| 찾기 | 상단 검색창 (`Ctrl+F`). 맞는 일정만 또렷하게 남는다 |
| 되돌리기 / 다시 실행 | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 반출·반입 | **데이터** 패널 — JSON 파일로 저장하거나 불러온다 |
| 이전 시점으로 | **데이터 › 변경 이력**에서 복원 |
| 인쇄 | 툴바 인쇄 버튼. 툴바와 패널은 빠지고 보드만 나온다 |

## 데이터

문서 하나가 보드 하나다.

```jsonc
{
  "version": 1,
  "meta": { "start": "2026-09-21", "end": "2027-04-04" },
  "tracks": [ { "id": "t0", "lab": "요구사항 4", "name": "통합 모니터링 시스템" } ],
  "items": [{
    "id": "e10",
    "t":  "t0",           // 트랙 id
    "sp": 1,              // 트랙 병합 폭
    "s":  "2026-10-01",   // 시작
    "e":  "2026-10-31",   // 종료 (inclusive)
    "ti": "1년차 과제 제출용 화면 구성",
    "ty": "bar",          // bar | ms(마일스톤)
    "st": "run",          // plan | run | done | late | hold
    "og": "다임리서치",
    "pg": 20,             // 진척률
    "dp": ["e2"],         // 선행 일정 (표시 전용)
    "note": ""
  }]
}
```

SQLite 안에서는 `board` · `track` · `item` · `dependency` · `revision` 테이블로 정규화돼 있어
조직별·기간별 집계나 선후행 추적을 SQL로 바로 할 수 있다.

상태·담당 조직 목록은 `src/config/index.js`에서 바꾼다. 코드를 고칠 필요 없다.
