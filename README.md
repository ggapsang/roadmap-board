# WOLFPACK

<img src="assets/icon.png" width="96" alt="WOLFPACK">

일정을 **시간축 위에 정렬된 상태로** 편집·공유하는 데스크톱 보드.
마스코트는 펜리르(Fenrir). 북유럽 신화에 등장하는 늑대. 집중력과 끈기의 상징. 목표를 향해 꾸준히 나아가는 모습. 

구글 캘린더 일간 화면에서 영감을 받았음 — 세로는 시간, 가로는 병렬 트랙.
PPT 도형으로 관리하던 일정을 옮겨, 주간 갱신과 선후행 추적이 가능하게 하는 것이 목적이다.

> 공수·원가·리소스 배정·결재는 이거랑 관계 없음. 칸반식 WBS는 대체할 수도 있음(프로젝트 성격에 따라). 이 도구는 **보고·합의용 시각화 보드**이며 PMS로 업그레이드는 나중 일.

> **더 큰 그림.** 이 로드맵 보드는 더 일반적인 구조인 **순서 기반 이벤트 전개 시스템**의
> 첫 활용 예다 — "달력 눈금을 쓰고, 트랙은 과제이며, 관계는 선행이고, 보드는 하나"라는
> 설정값을 박은 상태. **시스템 개념의 최종 기준은 [docs/SYSTEM.md](./docs/SYSTEM.md)**(코드보다
> 우선)다. 화면의 말(동일·조합·별칭·보드·트랙·카드)을 시스템 개념으로 그대로 옮기지 않는다 —
> 시스템에는 **이벤트와 관계(포함·선행·합류·원인·참조)** 만 있다. 개념·확장 방향은 SYSTEM.md와
> `refs/TTB-*.pdf`에, 이 코드에서 크게 틀렸던 것과 교훈은 [docs/LESSONS.md](./docs/LESSONS.md)에 있다.

## 실행

```bash
npm install
npm start
```

Electron 앱이 뜨면 **프로젝트 목록**이 먼저 나온다. 보드 하나가 프로젝트 하나이고,
과제·연차마다 따로 만들어 쓴다. 데이터는 SQLite 파일 하나에 자동 저장된다.

| 명령 | 설명 |
|---|---|
| `npm start` | 앱 실행 |
| `npm run dev` | 개발자 도구를 함께 연다 |
| `npm test` | 스모크 — 창을 띄워 렌더와 저장 왕복을 확인하고 종료 |
| `npm test -- --shot ./shots` | 위에 더해 화면을 PNG로 남긴다 |
| `npm start -- --db ./machina.db` | DB 파일을 직접 지정 (과제별로 나눠 쓸 때) |
| `npm run dist` | Windows 64비트 설치 파일·포터블 exe 생성 → `dist/` ([배포](#배포)) |

DB 기본 위치는 `%APPDATA%/wolfpack/wolfpack.db` — 메뉴의 **파일 › DB 파일 위치 열기**로 바로 갈 수 있다.

## 배포

다른 사람에게 줄 때는 설치 파일을 만든다 (Windows 64비트).

```bash
npm run example-db   # (선택) 지금 쓰는 DB를 예시로 떠 둔다 → build/example.db
npm run dist
```

`build/example.db`가 있으면 설치 파일에 함께 들어가, 받는 사람이 **처음 실행할 때 그 예시 보드들로 시작**한다
(이미 DB가 있는 PC에서는 덮어쓰지 않는다). 예시에는 변경 이력·휴지통을 빼고 담는다. 원본 DB는 건드리지 않고,
`build/example.db`는 저장소에 올라가지 않는다(`.gitignore`의 `*.db`). 예시를 새로 하려면 `npm run example-db`를 다시 실행한다.

`dist/`에 두 가지가 생긴다.

| 파일 | 설명 |
|---|---|
| `WOLFPACK Setup {버전}.exe` | 설치 파일. 관리자 권한 없이 사용자 계정에 설치되고, 설치 경로를 바꿀 수 있다. 시작 메뉴·바탕화면 바로가기와 제거 프로그램이 함께 생긴다 |
| `WOLFPACK {버전}.exe` | 포터블. 설치 없이 exe 하나로 실행(USB·아무 폴더). 실행할 때마다 임시 폴더에 풀어서 켜므로 조금 느리고, 바로가기·제거 항목이 없다 |

- **처음 실행할 때 "Windows의 PC 보호" 경고가 뜬다** — 코드 서명 인증서가 없어서다. **추가 정보 › 실행**을 누르면 된다.
- 데이터는 설치판·포터블 모두 각자 PC의 `%APPDATA%\wolfpack\wolfpack.db`에 저장된다(포터블도 exe 옆이 아니다). `npm start`로 쓰는 것과 **같은 폴더**라,
  한 PC에서 설치판과 `npm start`를 함께 쓰면 같은 보드가 보인다(둘을 동시에 켜 두지는 말 것).
- 새 버전을 낼 때는 `package.json`의 `version`을 올린 뒤 다시 만든다. 설치 파일을 다시 실행하면 덮어 설치되고 데이터는 그대로 남는다.
- 다른 사람과 보드를 나눌 때는 **데이터 › 반출**(JSON)로 파일을 주고받는다 — DB는 PC마다 따로다.

## 쓰는 법

### 프로젝트

첫 화면에서 열 프로젝트를 고른다. **새 프로젝트**는 빈 보드로 시작하고,
**예시 로드맵으로 시작**은 Project Machina 1차년도 일정이 들어간 보드를 만든다.
각 항목에서 복제·이름 변경·삭제를 할 수 있다. 보드를 보는 중에는 툴바 왼쪽
**프로젝트**로 목록에 돌아간다.

보드끼리는 기본적으로 따로다 — 트랙·담당 조직·일정을 공유하지 않는다. 다만 **합치기(동일)** 로 두
이벤트를 하나로 만들면 그 이벤트는 여러 보드에 함께 놓이고, 한쪽에서 고치면 모두 반영된다.
**조합**은 다른 보드의 여러 이벤트로 한 이벤트를 이루는 것이다(같은 보드의 이벤트는 이미 그 보드 안이라 조합할 수 없다).

### 보드

| 하고 싶은 것 | 조작 |
|---|---|
| 일정 옮기기 | 카드를 끈다. 위아래는 날짜(날짜 없는 보드는 칸), 좌우는 트랙. 정밀도는 눈금이 정한다 |
| 세로축 눈금 | **설정 › 표시 › 세로축 눈금** — 주-일 · 월-주(기본) · 분기-월 · 눈금 없음. 표시만 바뀐다. 구간 묶기·높이는 눈금마다 따로. 날짜 없는 보드는 새 보드를 만들 때 **눈금 없음**으로 → [docs/SCALE.md](./docs/SCALE.md) |
| 기간 늘리기 | 카드 **위** 가장자리를 끌면 시작일, **아래** 가장자리를 끌면 종료일이 움직인다 |
| 일정 안에 일정 넣기 | 편집 패널 **매핑 › 모자관계설정** — 부모를 고르거나, 품을 카드에서 자식들을 한꺼번에 고른다 |
| 안에 든 일정의 가로 폭 | 그 카드의 **좌·우** 가장자리를 끈다. 더블클릭하면 자동 배치로 돌아간다 |
| 카드 색 채우기 | **스타일** 탭 › **채우기** — 파워포인트·엑셀의 채우기처럼 카드 면 색을 고른다(× = 없음). 보드마다 따로. 왼쪽 상태 막대는 그대로 보인다 |
| 글자 세로 정렬 | **스타일** 탭 |
| 비고를 카드에 보이기 | 비고는 **속성** 탭에서 쓰고, 보드 카드에 보일지는 **스타일 › 비고 표시**(숨김 / 카드에 표시)로 정한다. 기본은 숨김 |
| 일정 만들기 | 빈 칸을 **클릭**하면 기본 길이(주-일 1일 · 월-주 1주 · 분기-월 1개월 · 눈금 없음 1칸), **끌면** 끈 길이만큼 생긴다. 툴바 **+ 일정**도 |
| 일정 고치기 | 카드를 클릭하면 우측 패널이 열린다. **속성·매핑·스타일·상세** 탭으로 나뉜다. 탭을 **끌어** 순서를 바꾸면 이 PC에 계속 기억된다. 다른 카드를 눌러도 보던 탭이 그대로 열린다 |
| 팝업 옮기기 | 떠 있는 팝업(고르기 트리·확인 창·휴지통)은 제목이나 빈 곳을 잡고 끌어 옮긴다 |
| 선행 잇기 | **매핑** 탭 › **선행관계설정** › **편집** → 같은 보드를 트리로 펼친 팝업에서 고른다 |
| 모자관계(카드 안에 카드) | **매핑** 탭 › **모자관계설정** › **편집** → 팝업의 **부모 설정**(이 카드를 품을 카드 하나) / **자식 설정**(이 카드에 넣을 카드들을 한꺼번에). 후보는 **같은 트랙 안의 카드만** 나온다. 자식 체크를 풀면 트랙 최상위로 나온다 |
| 항등 (합치기) | **매핑 › 항등설정 › 편집** — 다른 프로젝트의 이벤트를 골라 **하나로 합친다**(같은 이벤트로, 수학의 항등식처럼). 되돌리기 버튼 제공 |
| 조합 (구성) | **매핑 › 조합설정 › 편집** — **다른 보드의** 트랙·카드를 **둘 이상** 골라 이 이벤트를 이룬다(현재 보드의 이벤트는 목록에 안 나온다). 태스크와 다르다. 보드엔 카드로 안 그려지고 **상세 › 세부내역**에서 보인다. 트랙도 **설정 › 트랙**에서 조합할 수 있다 |
| 이벤트 복사·붙여넣기 | 카드 **우클릭 › 이벤트 복사** → 빈 칸 **우클릭 › 여기에 붙여넣기**. 하위 트리째 새로 만든다. **보드 간**에도 된다 |
| 탭(보드) 전환 | **Ctrl+Tab / Ctrl+Shift+Tab** 다음·이전, **Ctrl+T** 새 탭 (브라우저처럼). 탭을 **좌우로 끌어** 순서를 바꾼다 |
| 보드에서 빼기 | 카드를 고른 뒤 `Delete` 또는 `Backspace` — 안의 하위 카드째 빠진다. 이벤트는 **휴지통**으로 가고, 방금 만들었다 바로 지운 것은 그냥 없어진다. `Ctrl+Z`로 되돌린다 |
| 도움말 | 첫 화면 오른쪽 위 **?** 또는 `F1` — 사용법 팝업(`docs/HELP.md`). 시스템 개념 설명은 `docs/GUIDE.md` |
| 휴지통 | 첫 화면 오른쪽 위 🗑 버튼 → 팝업에서 **영구 삭제**(하나) · **비우기**(전부). 그 안에만 든 것이 함께 지워지고, 다른 보드에도 있는 것은 남는다 |
| 제목 줄바꿈 | 편집 패널 제목에서 `Shift+Enter` |
| 사이즈 수동 설정(가로·세로) | **스타일** 탭 › **사이즈 수동 설정**에서 **크기 강제**를 켜면 날짜와 무관하게 **좌·우** 가장자리로 폭, **아래** 가장자리로 세로 길이를 끈다. 끄면 자동 크기로 돌아간다 |
| 트랙 추가·순서·빼기 | 툴바 **⚙ 설정** 또는 헤더 오른쪽 **+**. 헤더를 **좌우로 끌어** 순서를 바꾼다(엑셀식). 트랙을 빼면 그 트랙에만 있던 카드가 함께 휴지통으로 가고, 다른 트랙에도 소속된 카드는 남는다 |
| 담당 조직 추가·이름변경·삭제 | 툴바 **설정 › 담당 조직** |
| 상태 이름 바꾸기 | 툴바 **설정 › 상태 이름** — 계획·진행중·완료·지연·보류를 보드마다 다른 이름으로 (색·의미는 고정) |
| 화살표 굵기·걸침 깊이·글자 크기 | 툴바 **설정 › 표시** |
| 글자 크기 | 툴바 **가− / 가＋**, 또는 `Ctrl` `+` / `-` / `0`(원래대로) |
| 상태·조직으로 거르기 | 상단 요약 바의 칩을 누른다 |
| 찾기 | 상단 검색창 (`Ctrl+F`). 맞는 일정만 또렷하게 남는다 |
| 카드 글자 복사 | 툴바 **I** 버튼 (`Ctrl+I`) — 선택 모드. 켜는 동안 드래그 이동은 멈춘다 |
| 되돌리기 / 다시 실행 | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 그래프로 보기 | 툴바 **그래프** — 모든 보드의 이벤트를 원으로, 포함·관계를 선으로 한 화면에(읽기 전용). 세로는 소속의 깊이, 가로는 순서. **구조 중력·흐름 중력**으로 정렬 세기를 조절(0이면 방향 없음), 노드를 끌거나 휠로 확대·빈 곳을 끌어 이동. 노드에 올리면 이웃과 관계 이름, 누르면 정보. 원 크기 = 안에 든 이벤트 수. 보드와 무관한 **독립 탭**으로 열리고(첫 화면에서도), 탭 ×로 닫는다 |
| 반출·반입 | **데이터** 패널 — JSON 파일로 저장하거나 불러온다 |
| 이전 시점으로 | **데이터 › 변경 이력**에서 복원 |
| 내보내기 | 툴바 **내보내기** — PNG · PDF · 인쇄 |
| 왼쪽 달력 칸 묶기 | 월 칸을 세로로 끈다 → 이름 입력 (예: 1~3월 → `2027 1Q`) |
| 칸 높이 조절 | 칸 **아래 가장자리**를 세로로 끈다. 낱개 월도 병합 없이 줄이거나 늘린다(그 구간의 일정도 같이) |
| 칸 · 구간 우클릭 | 이름 변경 · 해제 · **이 칸 접기** · **이 아래 빈 구간 삭제** |
| 뒤쪽 빈 구간 삭제 | 빈 날짜 칸 우클릭 → **이 아래 빈 구간 삭제**. 다시 카드를 아래로 끌면 축이 늘어난다 |
| 트랙 열 너비 | 트랙 헤더 오른쪽 가장자리를 끈다. 더블클릭하면 자동으로 되돌아간다 |
| 일정이 여러 트랙에 걸치게 | 카드 **오른쪽** 가장자리를 끈다 (트랙 칸 단위로 붙는다). 편집 패널 **속성 › 소속 트랙**에서 떨어진 트랙도 고를 수 있다 |
| 편집 패널 폭 | 패널 왼쪽 가장자리를 끈다 |
| 편집 패널 고정 | 패널 우측 상단 압정 버튼 — 켜면 Esc로도 닫히지 않는다 |

```jsonc
  "relations": [ { "id": "r1", "type": "dep", "from": "e2", "to": "e10" } ], // 지금은 선행(dep)만. 포함은 item.parent에서 파생
  "compose": [ { "parent": "e10", "child": "track:2:t3" } ], // 조합(구성) — 이 이벤트를 이루는 다른 보드의 이벤트들. 카드로 안 그림
  "items": [{
    // ── 이벤트 본질 (어느 보드에서 보든 같아야 하는 것) ──
    "id": "e10",
    "s":  "2026-10-01",   // 시작 — 날짜 없는 보드(dated:false)에선 null일 수 있다
    "e":  "2026-10-31",   // 종료 (inclusive)
    "ti": "1년차 과제 제출용 화면 구성",
    "ty": "bar",          // bar | ms(마일스톤: s==e면 시점, s<e면 기간)
    "st": "run",          // plan | run | done | late | hold
    "og": "다임리서치",
    "pg": 20,             // 진척률
    "note": "",
    "parent": null,       // 상위 일정 id — 있으면 그 카드 안에 들어간다(포함 관계, 렌더용 사본)
    "tasks": [ { "id": "k1", "text": "레퍼런스 수집", "done": true } ], // 순서 없는 할 일
    // 관계는 item이 아니라 따로 있다: 선행=doc.relations, 조합(구성)=doc.compose, 동일=합치기 '작업'(관계 아님)
    // ── 이 보드에서의 배치·표시 (보드마다 다를 수 있는 것) ──
    "place": {
      "t":  "t0",         // 트랙 id
      "sp": 1,            // 트랙 병합 폭
      "x": null, "w": null, // 칸/상위 카드 안에서의 가로 위치·폭 비율 (null = 자동)
      "hd": null,         // 크기 강제 시 세로 길이(일). null = 기간(s~e)대로
      "align": "middle",  // 글자 세로 정렬 top | middle | bottom
      "showNote": false,  // 비고를 카드에 표시 (기본 숨김 — 스타일 탭)
      "fill": null,       // 색 채우기 — 팔레트 key(gray·red·yellow·green·teal·blue·purple·pink) 또는 null
      "slot": null,       // 날짜 없는 보드에서의 칸 {s(0부터), len}. 날짜 있는 보드는 null
      "alias": null       // 별칭 — 이 배치에서만 다르게 보일 이름(표현). 본질 제목 ti는 안 건드린다
    }
  }]
}
```

> **본질과 표시를 나눈다.** `item`은 이벤트의 **본질**(어느 보드에서 보든 같아야 하는 것)과
> 이 보드에서의 **배치·표시**(`place`, 보드마다 다를 수 있는 것)를 나눠 담는다. 같은 이벤트가 여러
> 보드에 놓이면 본질은 하나를 함께 쓰고, `place`는 보드마다 따로다 → [docs/DIRECTION.md](./docs/DIRECTION.md) #1.

PNG와 PDF는 화면에 보이는 부분이 아니라 **트랙 헤더부터 마지막 일정까지 전체**를
한 장에 담는다. PNG는 2배 해상도, PDF는 보드 크기에 맞춘 단일 페이지다.

SQLite 안에서는 **4대상 모델**로 정규화돼 있다 — `event`(이벤트 본질) · `containment`(포함) ·
`disp`(배치·표시) · `rel`(관계, 지금은 선행 dep). 포함은 `ordered`·`compose` 두 칸으로 세 종류다:
순서 있는 포함(트랙 위 카드·하위 카드), 태스크(순서 없는 포함), 구성=조합(**보드→트랙**, 이벤트→조합
대상). 여기에 보드 레지스트리·설정(`board`, `meta_json`으로 표시 설정·상태 이름) · `org` · `band` ·
`revision`이 붙는다. 보드는 저장 단위가 아니라 '펼친 이벤트'이고, `board` 한 행이 프로젝트 하나다.
**같은 이벤트가 여러 보드에 놓일 수 있다**(다중 소속).

저장은 **보드가 본 것만 고친다** — 보드 문서로 전체를 덮어쓰지 않고, 그 보드가 연 상태와 비교해 바뀐
것만 쓴다. 그래서 여러 탭에 같은 이벤트가 열려 있어도 서로의 편집을 지우지 않는다. 보드를 지우면 그
보드에만 담긴 일정은 지워지고, 다른 보드에도 놓인 일정은 구조째 남는다 → [docs/SAVE.md](./docs/SAVE.md).
(마이그레이션은 `electron/db/migrations/NNN_*.sql`, 번호 순. 적용 전에 DB를 `*.bak`으로 백업한다.)

**트랙 축에는 정해진 의미가 없다.** 요구사항으로 쓰든 작업패키지로 쓰든 조직이나
설비로 쓰든 사용자가 정한다. `lab`은 위에 작게 붙는 자유 라벨일 뿐이다.

선후행 화살표는 같은 트랙이면 카드 아래에서 위로, **다른 트랙이면 측면끼리** 잇는다.
카드 사이 틈이 좁으면 화살표가 점처럼 보이므로 **양쪽 카드에 걸쳐** 길게 뽑는다.
굵기·머리 크기·걸침 깊이는 설정 패널에서 조절하고 문서에 함께 저장된다.

**담당 조직·상태 이름은 보드 안에서 편집한다** (설정 › 담당 조직 / 상태 이름). 프로젝트마다
다르다. 조직명은 일정에 문자열로 들어가므로 이름을 바꾸면 그 조직이 담당한 일정도 함께
갱신된다. 상태 5종의 **key·색·의미**(완료=흐림, 지연=강조, 보류=점선)는 `src/config/index.js`에
고정이고, 보드마다 바꿀 수 있는 건 그 **이름**뿐이다(`meta.statusLabels`).

## 디자인

다임리서치 UI/UX 가이드라인 v1.0을 기준으로, WOLFPACK Light / Dark UI Design Guide
(`refs/`)를 세부 규격으로 따른다. 요점은 셋이다.

- 정보 계층은 색이 아니라 **Surface 깊이 · 여백 · 약한 Border**로 만든다.
  Light는 `neutral-50` 캔버스 위 흰 카드, Dark는 캔버스→트랙→카드→호버→선택으로
  단계마다 밝아지는 따뜻한 계열(`refs/WOLFPACK_Dark_UI_Design_Guide_Revised.md`).
- **Orange는 장식이 아니라 신호다.** 오늘 · 선택 · 진행 표시자 · 주요 CTA · 포커스에만 쓴다.
  카드 배경을 상태 색으로 칠하지 않는다.
- 브랜드 마크(FENRIR)는 앱 아이콘 · 런처 · 툴바 브랜드 영역에만 둔다. UI 곳곳에 반복하지 않는다.
